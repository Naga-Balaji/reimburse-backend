The problem

Three pains, one messy inbox.

The problem statement gave me the pain points. The pack gave me the actual data.

PAIN 01

Manual assembly from chaos.

Uber receipts, a hotel folio with laundry mixed in, a colleague's expense forwarded to your inbox by accident, a duplicate resend of the same trip. Employees stitch this into a 50-field Excel form. Every time.

PAIN 02

Errors leak through.

Non-reimbursables get claimed. Duplicates get paid. Policy limits get missed. The paper form doesn't know Bengaluru is a Tier-1 city or that laundry isn't reimbursable — the human filling it has to remember.

PAIN 03

Silent workflow.

The employee submits, then chases Finance for two weeks. Manager doesn't know it's stuck. Finance doesn't know the employee is waiting. Nobody sees the audit trail — because there isn't one.

What the app does

Twelve features that make it real.

Every one maps to a specific line in the problem statement or the policy.

📥

Import from Inbox

Upload .eml files → deterministic parsers extract Uber, hotel, dinner receipts in seconds.

🤖

LLM fallback

Unknown senders? OpenRouter (Claude/DeepSeek) picks up the slack, opt-in on the import screen.

🚫

Noise filtering

Duplicates, colleague forwards, promo emails, payment failures — auto-detected and excluded.

⚖️

Policy engine

Lodging tier caps and non-reimbursable splitting enforced at save-time. Silent drops? Never.

🔀

Two-stage approval

Travel Request pre-trip. Expense Claim post-trip. Different reviewers, different jobs.

🪜

Tiered approvals

Amount decides the chain. Manager → HoD → Division → MD escalates automatically.

🧠

AI Verification Assistant

Recommends approve/return/reject with 87% confidence. Never auto-decides. Advisor, not autopilot.

📊

Employee Context

Past history, spending patterns, plan-vs-actual variance — the manager doesn't decide in a vacuum.

💰

Advance audit track

Disbursement is a distinct Finance event with its own reference. Sub-tree under the main workflow.

💬

Finance ↔ Employee thread

Advance on hold? Finance leaves a reason. Employee replies with clarification. Full audit trail.

📎

Proof viewer

Native inline rendering for .png, .pdf, .eml. Approvers verify with their own eyes, not blind trust.

🛡️

Admin oversight

Policy view, org tree, system-wide stats. Oversight, not operations — no approve buttons.

System architecture

Three services. One story.

Client. API. Database. Plus one AI integration — as a safety net, not the core.

Design principle: the shape of the code mirrors product thinking. core/parsers.py is a first-class file (not buried in utils/) because reading the inbox is the product. core/llm.py is separated from views.py because AI is an integration, not the core. If the LLM is down, the app still works.
Why this stack

Every choice has an alternative I rejected.

Not "what's popular" — what's fastest to build the right thing.

Backend
Django + DRF
Not Node/Express — DRF's viewsets + queryset-level RBAC compress a week of Node scaffolding into a day. Model changes → migrations → API in minutes.
Frontend
React + Tailwind
Not Next.js — no SSR needed; this is an internal tool. Not MUI/Bootstrap — they feel like consumer apps, not enterprise SaaS.
LLM
OpenRouter
Not the OpenAI/Anthropic SDK directly — OpenRouter lets me swap models with an env var, no code change. And it's cheaper.
Database
PostgreSQL
Not MongoDB — the domain is relational (users, approvals, hierarchies, joins). Django's ORM + Postgres is the friction-free path.
Auth
DRF Token
Not JWT — overkill for a single-frontend deploy. DRF's built-in Token auth is one line and works everywhere.
Typography
Inter + tabular numerals
Not the system font — financial apps need aligned digits. font-feature-settings: 'tnum' makes ₹ amounts scan cleanly.
Backend host
Railway
Not AWS/Heroku — 30-minute deploy from GitHub, auto-provisions Postgres, zero YAML. Ideal for a demo I want a reviewer to actually click.
Frontend host
Vercel
Not Netlify — near-identical DX. Vercel just felt smoother for Create React App. Auto rebuilds on git push.
